A 1 vCPU, 1 GB server with Docker is enough for a team. Tabletsgo itself uses about 150 to 250 MB of memory.

## Server

|        | Minimum  | Recommended              |
| ------ | -------- | ------------------------ |
| CPU    | 0.5 vCPU | 1 vCPU                   |
| Memory | 512 MB   | 1 GB                     |
| Disk   | 2 GB     | 5 GB, plus local backups |

More CPU makes it faster; more memory doesn't. Below half a CPU, start-up slows to several seconds and requests under load start
timing out. The measurements are in [the benchmark](https://github.com/aidapedia/tabletsgo/blob/HEAD/docs/BENCHMARK.md).

## Software

- **Docker** with Compose, on amd64 or arm64. The image carries everything else: Node.js, the PostgreSQL 18 and MySQL client tools
  for backups, and the store's migrator.
- **A current browser.** The console is a single-page app served by the same container.
- **Network access** from the container to the databases you connect, or to an SSH host in front of them.

## By mode

### Solo

Nothing else. The metadata store is a SQLite file in the volume, and the encryption key can be generated for you.

### Enterprise

A running [Hayat](https://github.com/aidapedia/hayat), which tabletsgo signs people in with. Hayat's own compose file runs it with
PostgreSQL and Redis. Tabletsgo needs to reach Hayat's service API from the server, and people's browsers need to reach Hayat's
sign-in pages. See [Enterprise mode](/docs/enterprise).

<H2 id="databases">Databases you can connect</H2>

| Engine                                  | Status    |
| --------------------------------------- | --------- |
| PostgreSQL, MySQL, SQLite, Redis, Kafka | Supported |
| MariaDB, MongoDB                        | Planned   |

An instance admin chooses which of them the instance offers: see [Modules](/docs/modules).
