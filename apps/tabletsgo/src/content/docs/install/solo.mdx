Solo mode is Tabletsgo for one person: one owner and nothing else to run. A new instance starts in it when no `HAYAT_*` setting is
present.

## Install

<CodeTabs>
  <Tab label="docker run">
    ```bash
    docker run -d --name tabletsgo \
      -p 3000:3000 \
      -v tabletsgo-data:/app/data \
      --restart unless-stopped \
      ghcr.io/aidapedia/tabletsgo:latest
    ```
  </Tab>
  <Tab label="Compose (from the repo)">
    ```bash
    git clone https://github.com/aidapedia/tabletsgo.git && cd tabletsgo
    cp .env.example .env    # nothing in it is required for solo
    docker compose up -d
    ```
  </Tab>
</CodeTabs>

## First run

Until it has an owner, every start prints a six-word setup code:

```bash
docker logs tabletsgo
# 🔑 Solo setup: open http://localhost:3000 and enter this code: amber-orbit-river-stone-maple-otter
```

Open the address, enter the code, your name, email and a password of at least 8 characters. Only someone who can read the server's
log can claim the instance, even if its port is open to others.

## Encryption key

With `ENCRYPTION_KEY` unset, a new SQLite install generates one into `/app/data/encryption.key`.

- Back that file up with the volume: without it, saved credentials can't be read.
- To keep the key apart from the data, set `ENCRYPTION_KEY` (`openssl rand -hex 32`) before the first start.
- An existing store started without its key refuses to start. With PostgreSQL as the store, always set the key yourself.

## Signing in

A session is a 15-minute access token, renewed from a 30-day `HttpOnly` cookie. Five failed attempts from one address lock it out for a
minute. Changing the password, or **Setting → Account → Sign out everywhere**, ends every session.

Under **Setting → Account** you change your name, email, time zone and password.

### Forgotten password

On the server:

```bash
docker exec tabletsgo npm run solo:reset-password
# ✅ New password for dev@example.com: 4kQ0p3m-Xv8sL2aZ
```

Add `-- --password 'a-long-new-one'` to choose it yourself. Every session ends.

## What solo leaves out

There is nobody else, so there are no member lists, no per-connection access lists and no ownership transfer. Need a team? [Move to
enterprise](/docs/solo-to-enterprise).
