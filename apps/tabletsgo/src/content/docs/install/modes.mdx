The same image runs Tabletsgo for one person or for a team. The difference is where people and their access live. Both modes are
free.

<ModeDiagram />

|                   | <Badge kind="accent">Solo</Badge>  | <Badge kind="info">Enterprise</Badge>              |
| ----------------- | ---------------------------------- | -------------------------------------------------- |
| For               | One developer                      | A team                                             |
| Runs              | Tabletsgo alone                    | Tabletsgo and Hayat ([bundled](/docs/enterprise#bundled) or your own) |
| Who signs in      | One owner, with email and password | Anyone Hayat lets in, one account across your apps |
| People and access | Just the owner, who can do anything | Workspaces, rosters and grants in Hayat's console |
| Required settings | None                               | `ENCRYPTION_KEY`, `HAYAT_ISSUER`, `HAYAT_API_URL`  |

Everything else is the same: the console, databases, dashboards, workflows, backups, modules, mail and updates.

## Which mode starts

On every start, in this order:

1. `TABLETSGO_MODE`, when it is set to `solo` or `enterprise`.
2. Otherwise, the mode the instance recorded the first time it started.
3. Otherwise, on a new instance: enterprise when `HAYAT_ISSUER` is set, else solo.

<Callout kind="note" title="An enterprise instance never falls back to solo">
  An instance that has run in enterprise mode refuses to start in solo mode, even if its `HAYAT_*` settings go missing. A lost setting
  never turns a team's instance into an open solo one.
</Callout>

## Changing mode

- **Solo to enterprise** is supported, with your data: [Solo to enterprise](/docs/solo-to-enterprise).
- **Enterprise to solo** isn't supported in place: export the connections you want and import them into a new solo instance.
